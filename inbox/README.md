# Inbox — upload here

Upload model outputs here through GitHub web: open this folder → **Add file** → **Upload files**.

## How a test becomes three installable apps

1. Each test gives **three files**, `v1`, `v2` and `v3`. Upload each one separately, renamed exactly like this:

   ```
   {test}__{model}__{YYYY-MM-DD}__v{n}.html
   ```

   - `test` is one of the fifteen slugs in `prompts/catalog.json`: `site-brand`, `site-editorial`, `site-store`, `game-2d`, `game-3d`, `game-duel`, `vis-image`, `vis-motion`, `vis-3d`, `story`, `music`, `toy`, `teach`, `sim`, `idea`.
   - `model` is lowercase, with hyphens and dots, for example `claude-sonnet-4-5`, `glm-5.3-flash`, `gpt-5`.
   - `v{n}` is `v1`, `v2` or `v3`. A retest of the same prompt starts at `v4`. Never overwrite a run.
   - Only `.html` (or a `.zip` with `index.html` at its root). Never `.rar`.

2. The Action moves each file to `runs/{date}_{model}_{test}_v{n}/index.html` and writes these files **next to it**:

   | File | Purpose |
   |---|---|
   | `meta.json` | scores (start empty), notes, and `pwa` (did the HTML link the manifest and register the worker?) |
   | `manifest.webmanifest` | install name, colours, icons, `start_url` |
   | `sw.js` | service worker: the run works offline after one visit |
   | `icons/icon-192.png`, `icons/icon-512.png` | install icons, generated by the tool |

   The model's `index.html` is **never edited**. The prompt makes the model link the manifest and register `sw.js` in its own `<head>`. The tool only supplies those files.

3. The dashboard lists the run. Each run's install address is:

   `https://itsnotalwin.github.io/modelbench/runs/{date}_{model}_{test}_v{n}/index.html`

   Open it on a phone and choose **Add to Home Screen** (iPhone Safari: Share → Add to Home Screen; Android Chrome: menu → Install app).

## Checks

- A card marked **not installable** means the uploaded HTML does not link `manifest.webmanifest`. It still runs in the browser but cannot be installed. Re-upload as `v{n+1}` after the model adds the head tags, or keep it as a browser-only result.
- Installing needs HTTPS. GitHub Pages provides it. `file://` and local test servers without HTTPS do not install.
- Folder uploads (`.zip`) work the same way: the assets are added beside the folder's `index.html`.
- Rejected names stay here untouched. Rename the file and upload it again.
