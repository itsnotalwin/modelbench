## The brief

Build **Pulse Loom**, one expressive browser-based music workstation. It combines a playable step sequencer with a small synthesiser and a visual rhythm display. It should feel like an instrument someone could enjoy using, not a matrix of buttons that emits random beeps.

All sound must be generated by the Web Audio API. Do not use copyrighted songs, commercial samples, remote audio files or external sound libraries.

## Product requirements

1. Create a clear musical workspace with a 16-step timeline, at least four independently controllable voices and a strong visual playhead. The interface must communicate which steps are active and which voice owns each row.
2. Give each voice a distinct synthesised sound architecture, such as a tuned oscillator voice, plucked/decaying voice, noise/percussion voice and sustained pad. Timbres should be recognisably different and have meaningful controls.
3. Implement tempo control, swing, transport play/stop, step reset, pattern clear and per-voice mute/solo. The playhead must remain in sync without accumulating timing drift.
4. Provide at least three musical scales or modes. Notes must be quantised to the selected scale. Changing the scale must update the note choices without silently destroying the user's pattern.
5. Let the user edit steps by mouse, touch and keyboard. Include useful velocity or accent control and a way to change pattern length or variation.
6. Add at least three musical pattern presets that demonstrate different rhythmic ideas. Include a “surprise” or controlled randomise action that stays in the selected scale and has a clear undo/reset route.
7. Provide sound-shaping controls for each voice, master level and a visible level/spectrum or waveform display derived from the generated audio. Prevent clipping and runaway volume.
8. Persist patterns and workstation settings locally. Support JSON pattern export/import with validation.
9. Add WAV export of the current pattern using offline rendering or a correct AudioBuffer-to-WAV encoder. The exported file must contain the same programmed pattern and tempo, not a silent placeholder.
10. Respect browser audio rules: audio starts only after a user gesture, the user can stop sound immediately, and the app explains when audio is suspended or unavailable. No sound should play automatically on page load.

## Quality bar

The workstation should have a coherent sonic and visual identity. Use careful spacing, strong contrast, subtle animation that supports rhythm, readable controls and good touch targets. Avoid visual clutter. Every control must affect the audio or the pattern in an understandable way.

Use one self-contained HTML file with inline CSS/JS and the native Web Audio API. No external libraries, remote fonts, sample files, API keys, backend or build tools. Use accessible labels, keyboard navigation, reduced-motion support and no console errors.

## Acceptance checklist

Before finishing, verify that:
- Four voices produce distinct, audible synthesised sounds after a user gesture.
- Sequencer steps, velocity/accent, tempo, swing and scale affect playback as described.
- Mute and solo work independently per voice.
- Playback remains stable for a multi-minute run without noticeable timer drift.
- Stop immediately silences playback and page load produces no sound.
- Presets, randomise, clear and reset work.
- Patterns and settings survive reload; JSON export/import round-trip successfully.
- WAV export has a valid header, non-zero audio data and matches the programmed pattern.
- The interface works at desktop and phone widths.
