## Model prompt (send everything below this line)

Build **three separate image studios**, each as its own single HTML file. Each studio generates one original picture, and each uses a different technique. There is **no external image or AI API**. The picture must be generated by your code at runtime: canvas 2D, SVG, a WebGL fragment shader, or a mix. You may not embed image data, load image files, or call any service.

Techniques you could choose from, one per file: noise-field terrain, flow fields, L-systems or recursive trees, a Truchet or tiling system, a ray-marched or signed-distance-field scene in a shader, a halftone or dithering pass over a procedural composition, a Voronoi or Delaunay mosaic, a reaction-diffusion pattern, a typographic poster built from code. The three techniques must be different.

**Ground rules (apply to all three)**
- You choose the names, subjects and look. Do not ask questions and do not hedge. Decide and build.
- Each file is self-contained, with no external files.
- Each must open directly from disk (`file://`) and work on GitHub Pages from a subfolder.
- No placeholder art, TODOs or dead controls.

**What each studio must do**
- A large render of the picture, at a resolution suitable for print or a large screen.
- A **seed** input and a randomise button. The output must be reproducible: the same seed gives the same image. Use a seeded PRNG, never `Math.random`.
- At least **three parameter sliders** with live re-rendering.
- A palette derived by your code (for example from a colour theory rule or a sampled gradient), shown as swatches.
- **Download PNG**, via `canvas.toDataURL` or `toBlob`.
- A short note on what the technique is doing and what you would change next.

**Quality bar**
- Judge yourself on composition, colour, texture, and whether the output is surprising.
- No generic gradient placeholders.

**Mobile-first and installable (mandatory, every file)**
- Design for a 390px-wide portrait phone first, then scale up to desktop. Touch is the primary input: every control is at least 44px, nothing depends on hover, and the first interaction works with one thumb.
- Works in portrait and landscape, handles `resize` and `orientationchange`, and respects `env(safe-area-inset-*)` so nothing hides behind a notch or the home bar.
- Fits the screen: use `100dvh`, no page scrolling in games and toys, and `touch-action` set on play areas so pinch and double-tap do not zoom the page.
- Mobile specifics for this test: a studio that works one-handed: thumb-sized sliders, parameters in a bottom sheet, a large preview that fits the screen, and PNG saving that works from the phone's share or save sheet.
- The file must be installable as a Progressive Web App. The benchmark host places `manifest.webmanifest`, `sw.js` and `icons/` next to your file. Your file must reference them. Put exactly these lines in `<head>` (set `theme-color` to your own palette colour):

```html
<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">
<meta name="theme-color" content="#0b0d12">
<meta name="mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
<link rel="manifest" href="manifest.webmanifest">
<link rel="icon" href="icons/icon-192.png" sizes="192x192" type="image/png">
<link rel="apple-touch-icon" href="icons/icon-192.png">
```

  and this line just before `</body>`:

```html
<script>if ('serviceWorker' in navigator) navigator.serviceWorker.register('sw.js').catch(() => {});</script>
```

- Do not create the manifest, service worker or icon files yourself. The file must still open and work from disk even when they are missing. Once installed, the app must run offline after its first load, so keep runtime network use to the CDN libraries your prompt allows.

**Delivery — naming is mandatory**
- File names are `image__{model-slug}__{YYYY-MM-DD}__v1.html`, then `…__v2.html`, then `…__v3.html`.
  - `{model-slug}`: your model name in lowercase, hyphens for spaces, dots kept when they are part of the name (for example `glm-5.3-flash`).
  - `{YYYY-MM-DD}`: today's date.
  - No creative file names, no uppercase letters, no spaces.
- Deliver the three files in order. Before each one, write its exact file name on its own line. Then the complete file in one code block.
- After the third file, give one short bullet list per studio: its technique, the key creative choice, and one known limitation. Nothing else.
