# ModelBench

Benchmark inspector for model outputs. Twenty prompts, each with its own **unique category slug** so runs never collide by category — **4 core builds** (website, SaaS for clearing agents, 2D game, 3D game), **8 single-file builds v2** (restaurant site, machine explainer, first-person game, arcade game, browser OS, Rubik's cube + solver, original platformer, living 3D world), and **8 new builds** (data story, generative art, music instrument, creative tool, emergent sim, strategy game + AI, spreadsheet, physics engine) — one dashboard to preview, filter, compare and score every attempt.

**Scoring (0–5 each):** completeness, robustness, craft, depth, originality, performance — plus a log of whether it ran on first open, console errors, FPS and file size. The rubric is in [`prompts/README.md`](prompts/README.md); the dashboard reads the same six axes from each run's `meta.json`.

**Live dashboard:** https://itsnotalwin.github.io/modelbench/

## How to add a test (30 seconds, no terminal)

All four prompts already require the model to self-name its output and to put a runnable `index.html` at the root, so uploads are previewable and comparable online.

1. Generate the output with a model using a prompt in [`prompts/`](prompts/).
2. Zip the folder (website / SaaS) or take the single `.html` (games). If the model ignored the naming rule, rename the folder to `{date}_{model}_{category}_v{n}` yourself.
3. Name the upload **category first, double underscores** — e.g. `website__glm-5.3-flash__2026-11-06__v1.zip`, `game2d__crouton-alpha__2026-11-06__v2.html`. Never `.rar`, never the run-folder name.
4. On GitHub, open [`inbox/`](inbox/) → **Add file → Upload files** → upload.
5. The **Auto-sort** Action moves it to `runs/{date}_{model}_{category}_v{n}/`, writes `meta.json`, rebuilds `manifest.json` and commits. The dashboard updates on GitHub Pages (allow ~1 min). Check the Action log if a file does not appear.

Full naming rules: [`inbox/README.md`](inbox/README.md).

## Dashboard (`index.html`)

Single-file, no dependencies, no build step — served from the repo root on GitHub Pages, or locally with `python -m http.server`.

- Filter by prompt / model, search, sort by date or score
- Preview any run in a sandboxed iframe (+ open in new tab)
- Side-by-side **compare** two runs for the same prompt
- Stats per category and model
- Scores come from each run's `meta.json`: `visual`, `functionality`, `prompt_following` (0–10), plus `notes`

Run folders are **never modified** by the dashboard — it only reads them.

## Layout

```
index.html                  dashboard (GitHub Pages entry)
manifest.json               generated by tools/build_manifest.py
prompts/                    the 4 benchmark prompts (+ upload filename per prompt)
inbox/                      drop uploads here → Action sorts them
runs/{date}_{model}_{category}_v{n}/   meta.json + index.html (model folder renamed to this prefix)
tools/                      sort_inbox.py, build_manifest.py, new_run.py (stdlib only)
.github/workflows/          auto-sort.yml
```

## Local use

```bash
python -m http.server        # dashboard at http://localhost:8000
python tools/new_run.py --model claude-sonnet-4-5 --category website   # prints the exact upload filename
python tools/sort_inbox.py   # sort inbox/ locally (same code the Action runs)
```
