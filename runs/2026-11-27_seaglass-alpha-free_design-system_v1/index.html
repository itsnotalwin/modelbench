Vireo · Design System · v1

A calm team workspace, built in pure HTML & CSS.

Vireo is an imaginary tool for small studios and research teams to run projects, capture notes, and keep decisions in one place. This is its complete, reusable design system: a considered token layer, accessible components with real states, layout rules, and a polished showcase — semantic HTML and CSS only. No JavaScript, no framework, no build step.

Foundations

Design tokens

Everything is driven by CSS custom properties. Raw primitives feed semantic tokens; restyle by overriding semantic tokens, not by editing components. Tokens live in assets/css/tokens.css.

Colour

Two layers: primitives (--paper-*, --ink-*, --teal-*, status hues) and semantic tokens (--c-bg, --c-text, --c-accent, --c-danger…). Semantic tokens remap automatically in dark mode (prefers-color-scheme). Always pair colour with text; never rely on hue alone.

Typography

System font stacks — no webfonts, no downloads, works offline. --font-sans, --font-serif, --font-mono. Scale is a 1.25 ratio in rem; headings use clamp() for fluid responsive sizing; body leading --leading-base (1.55); text-wrap: balance/pretty where supported.

Sizing & responsive breakpoints

Control heights: --control-height-sm 32px, --control-height 40px, --control-height-lg 48px. Content widths: --content-max 1200px, --prose-max ~42rem, --sidebar-width 16rem. Layout is fluid first; media queries add structure.

Borders & radii

Borders: --border-width 1px, --border-width-strong 2px, --c-border, --c-border-strong. Use borders before shadows for structure.

Elevation

Layered shadows, remapped for dark mode. --elevation-raised, --elevation-overlay. Focus uses a ring, not shadow.

  • --shadow-xs

Motion

Fast, subtle, purposeful. --duration-fast 120ms, --duration-base 200ms, --duration-slow 320ms; easings --ease-standard, --ease-out, --ease-in-out. Hover the button to feel it. Reduced motion: @media (prefers-reduced-motion: reduce) disables animation/transition.

Guidance.
  • One primary action per view. Keep labels verb-first (“Create task”, not “OK”).
  • Icon-only buttons need an accessible name (aria-label) and aria-hidden on the icon.
  • Loading buttons are disabled + aria-busy="true" with a “…” label; never trap keyboard users.
  • Disabled native buttons are inert; for links use aria-disabled + remove href target or use a <span>.

Links

Real destinations only. Underline on hover/focus; colour plus underline so links don't rely on colour alone. aria-current for current location; target="_blank" always with rel="noopener" and a warning.

Switch

Native checkbox + CSS, role="switch". On/off with immediate effect; pair with a visible label. Use aria-checked where CSS can't reflect state… here :checked handles it.

Accessibility

Vireo targets WCAG 2.1 AA. It works with keyboard alone, assistive technology, dark mode, reduced motion, and no JavaScript.

Semantic structure

  • One <h1>; ordered headings; landmarks <header>/<nav>/<main>/<aside>/<footer>/<section>.
  • Real controls (<button>, <a href>, <input>, <select>); no clickable <div>s; no dead links.
  • Lists for lists; <table> with caption + <th scope>; <dl> for key/value; <fieldset>/<legend>.
  • Skip link → #main; meaningful link text; aria-label for icon-only controls; aria-current, aria-pressed, aria-busy, aria-invalid, aria-describedby.
  • role="status"/role="alert"/role="dialog"/role="progressbar" where native semantics don't cover it.

Keyboard

  • Everything interactive is reachable + operable with Tab, Shift+Tab, Enter, Space; radios/checks use native arrow keys; <details> native; tabs are a native radio group.
  • Visible focus: 3px --c-focus ring, offset, never removed. :focus-visible.
  • Skip link appears on focus. Tables + scroll regions are keyboard-scrollable.
Tab moveShift+Tab backEnter activate linkSpace toggle↑↓←→ navigateEsc dismiss (native dialogs)

Contrast & colour

  • Body text ≥ 4.5:1, large text ≥ 3:1, UI/focus ≥ 3:1 in both light and dark themes.
  • Never colour alone: status = colour + icon + text; errors = text + icon + aria-invalid; links = colour + underline on hover.
  • Native color-scheme + form accent-color; automatic dark theme; honour prefers-reduced-motion; @media print.

Forms

  • Every input has a <label>; placeholders supplement, never replace.
  • Native validation + visible, linked error/success text; required marked (asterisk + required).
  • Helpful autocomplete, inputmode, type; error messages name the fix.

Honest limits (no JavaScript)

  • CSS-only tabs don't toggle aria-selected; CSS-only :target dialogs don't trap or move focus like native <dialog>. Keyboard use + clear close still work; add a few lines of JS if strict ARIA + focus management are required.
  • Search field submits a query; full-text filtering needs a backend or JS. Forms are fully interactive + natively validated but this static page sends nothing; a pure-CSS :target shows success.
