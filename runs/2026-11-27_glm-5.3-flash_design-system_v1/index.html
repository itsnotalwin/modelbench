Loam · design system · v1.0

A field notebook for restoration teams.

Loam is the design language of a fictional field-records platform used by habitat restoration crews — survey logs, species checklists and planting seasons. It favours calm, legible interfaces that hold up outdoors: a paper-warm neutral base, deep pine for anything interactive, hairline structure, and data set in tabular monospace.

6 colour ramps 11 component families 2 applied patterns 0 dependencies WCAG 2.1 AA targets

Principles

01

Field-first legibility

Body text never drops below 14 px, and values are set in tabular monospace so columns align even on a sun-bleached tablet.

02

Quiet structure

Hairlines and surface shifts do the layout work. Shadows are reserved for things that genuinely float above the page.

03

Earthy, not rustic

Six tight colour ramps sit on a paper base. Pine means interactive, clay accents the story, and status colours stay strictly semantic.

04

Honest interaction

Every control on this page works — tabs switch, tables sort, forms validate, dialogs open. A design system with dead buttons is a mood board.

Library

Components

Eleven families, one naming language: .component, .component--variant, .component__part. States are baked into every family — hover, focus-visible, active, disabled and loading come free with the class.

Buttons <button class="btn">

Use one primary button per view region. The hierarchy runs primary → secondary → ghost → quiet-danger; reserve --danger for irreversible actions like deleting a site.

Links <a href>

Use links for navigation, buttons for actions. Default links are pine-700 with an under-line that darkens on hover; quiet links trade the underline for weight in dense UI.

Use native <dialog> for decisions that need the user’s full attention — it traps focus, closes on Esc and returns focus to the trigger. Toasts confirm outcomes without interrupting; they use role="status" so screen readers announce them politely.

Accessibility

Loam targets WCAG 2.1 AA. The commitments below are implemented on this page — try them with the keyboard alone.

CommitmentHow Loam meets it
Keyboard completeSkip link, full tab order, arrow-key tabs, Esc closes dialogs and the mobile nav, focus returns to triggers
Visible focusOne focus ring token everywhere: 2 px pine outline, 2 px offset, on :focus-visible only
ContrastBody text ≥ 5:1, muted meta ≥ 5:1, primary-button text ≈ 5.6:1; colour never the sole signal (badges pair dots with labels)
FormsExplicit labels, hints, errors linked via aria-describedby, aria-invalid, focus moves to the first invalid field
Data tablesscope="col" headers, aria-sort announcements, row checkboxes with per-row labels
Live regionsToasts use role="status"; dialogs are native <dialog> with labelled titles
MotionEverything collapses under prefers-reduced-motion: reduce
Loam v1.0

Loam is a fictional product, invented for this design exercise: a field-records platform for habitat restoration crews. All sites, species, people and records are imaginary.

Built with semantic HTML, hand-written CSS custom-property tokens, and a small vanilla script for behaviour — no frameworks, no libraries, no build step, no external fonts or requests. Type renders from system stacks.
